# Real-user pilot checklist

## Before asking
- Identify one small business, freelancer or bookkeeper who handles invoices.
- Explain the prototype, which services receive data, what is stored, and what the prototype does not do.
- Ask for explicit permission. Participation must be optional.
- Do not request bank statements, payment credentials or more data than necessary.
- Prefer redacted copies or a small set of low-risk historical invoices.

## Privacy and safety
- Never upload customer invoices to an external LLM/OCR service without explicit informed consent.
- Redact addresses, tax IDs, bank details and personal data where possible.
- Agree on storage location, access, retention period and deletion date.
- Use sandbox accounting records only; never initiate payments.
- Keep customer data out of public repositories, demo recordings and screenshots.
- Provide a way to stop the pilot and delete the data.

## Pilot protocol
1. Observe the existing process without interrupting it.
2. Measure baseline hands-on time for a small sample.
3. Process the same documents with the prototype.
4. Have the user verify all extracted values; record corrections.
5. Report per-field accuracy, review time, end-to-end time, and failure modes.
6. Ask three questions: what saved time, what felt unsafe/confusing, what would prevent adoption?
7. Delete source documents on the agreed date and confirm completion.
